# استقرار «پایش» روی میزبان همیشه‌روشن (ابر)

این پوشه برای وقتی است که می‌خواهید سامانه ۲۴ ساعته در دسترس باشد و همهٔ
گوشی‌ها و رایانه‌ها با **یک آدرس ثابت HTTPS** به آن وصل شوند — بدون تونل،
بدون Tailscale، بدون اسکن شبکه و بدون تایپ آدرس.

> **نسخهٔ Node:** برنامه از `node:sqlite` استفاده می‌کند، پس به **Node 22.5 یا بالاتر** نیاز دارد.
> اگر پنل میزبانی فقط Node 18/20 می‌دهد، بالا نمی‌آید و باید بگویید تا مسیر جایگزین را آماده کنم.

---

## راه ۱ — هاست اشتراکی با پشتیبانی Node (همان تست ۶۰ روزه)

1. فایل ZIP آماده را بسازید (روی سیستم خودتان):
   ```bash
   node scripts/build-cloud-bundle.mjs
   # خروجی: releases/payesh-cloud.zip
   ```
2. در پنل میزبان: یک اپلیکیشن از نوع **Node.js** بسازید، نسخه را **22** بگذارید،
   و فایل ZIP را آپلود کنید (یا از GitHub وصل کنید).
3. **دستور شروع (Startup command):**
   ```
   node --experimental-sqlite --disable-warning=ExperimentalWarning server/index.js
   ```
4. **متغیرهای محیطی** (بخش Environment پنل):
   ```
   PORT=<پنل خودش می‌دهد؛ دست نزنید>
   PAYESH_DATA=/home/<user>/payesh/data      ← مسیر ماندگار، نه /tmp
   PAYESH_TUNNEL_AUTO=0                       ← روی ابر لازم نیست
   PAYESH_PUBLIC_URL=https://<آدرس نهایی همین اپ در پنل>
   ```
5. **پوشهٔ دادهٔ ماندگار:** هر جای پنل «Persistent storage / Disk» داشت، آن را به
   مسیر `PAYESH_DATA` وصل کنید. اگر نبود، پوشهٔ `data/` کنار خود پروژه بسازید —
   ولی بدانید بعضی هاست‌ها با هر ری‌استارت فایل‌ها را پاک می‌کنند؛ در این حالت
   داده از دست می‌رود (قبل از ورود دادهٔ واقعی حتماً تست کنید).
6. آدرس HTTPS پنل را باز کنید → «راه‌اندازی پایش-لوکال» → نام مدرسه، مدیر، شمارهٔ همراه و رمز عبور.
7. صحت را چک کنید:
   ```bash
   node deploy/selfcheck.mjs https://<آدرس نهایی>
   ```

**دام‌ها:** آدرس «موقت» («temporary URL») با هر ری‌استارت عوض می‌شود — برای
مدرسه بی‌فایده است؛ باید دامنه/زیردامنهٔ ثابت بگیرید. همچنین پلن‌های ارزان
اغلب بعد از چند دقیقه بی‌کاری می‌خوابانند؛ در پنل دنبال «Always On» باشید.

## راه ۲ — VPS (توصیهٔ من: پایدارترین)

روی اوبونتو ۲۲/۲۴، بعد از اینکه کد را در `/opt/payesh` گذاشتید:

```bash
sudo DOMAIN=payesh.example.ir bash deploy/vps-setup.sh
# بدون دامنه (فقط IP و پورت ۸۰۸۰):
sudo bash deploy/vps-setup.sh
```

اسکریپت این کارها را می‌کند: نصب Node 22، ساخت کاربر سرویس، `systemd`،
Nginx (اگر دامنه دادید) + SSL خودکار با Certbot، و بکاپ روزانهٔ ۳۰ روزه.

دستورها:

```bash
systemctl status payesh        # وضعیت
journalctl -u payesh -f        # لاگ زنده
sudo bash deploy/backup.sh     # بکاپ دستی
```

## راه ۳ — داکر (هر سروری، حتی خارجی)

```bash
docker compose up -d
# آدرس: http://SERVER:8080
```

داده در volume با نام `payesh-data` می‌ماند. بکاپ:
```bash
docker run --rm -v payesh-data:/d -v $PWD:/out alpine tar czf /out/payesh-backup.tgz -C /d .
```

## بعد از استقرار

1. در برنامه، پنل **مدیر → شبکه**: آدرس رسمی را همان `https://…` بگذارید.
2. آدرس را در `android-config.json` (کلید `url`) بگذارید تا **همهٔ گوشی‌ها**
   بدون تایپ وصل شوند — یا در نصب به کاربر بدهید.
3. روی سیستم مدرسه هم اگر می‌خواهید کپی محلی/آفلاین باشد، همان آدرس را در
   `C:\Program Files\Payesh\payesh.ini` با کلید `urls=` بگذارید.

## پشتیبان‌گیری

هر شب یک نسخه در `PAYESH_DATA/backups` ساخته می‌شود (روی VPS با cron).
بازگردانی: فایل `backups/*.sqlite` را روی `payesh.sqlite` کپی کنید و سرویس را ری‌استارت کنید.

## میزبان‌های پنلی رایگان (نمونه: Botkeep)

اگر پنل «Node.js + آپلود ZIP» می‌دهد و نسخهٔ Node قابل انتخاب است:

| کار | مقدار |
|---|---|
| Runtime | Node.js **22** یا **24** |
| Start command | `npm start` |
| Environment | `PAYESH_DATA` (مسیر ماندگار)، `PAYESH_PUBLIC_URL`، `PAYESH_TUNNEL_AUTO=0` |
| درگاه | دست نزنید — برنامه هم `PORT` را می‌خواند هم `SERVER_PORT` |
| دامنه | از تب **Domains** همان آدرس HTTPS را به سرویس وصل کنید |

نکته‌های واقعی این نوع پنل‌ها (از مستندات خودشان):

- سقف پلن رایگان رایج: **۵۱۲ مگ رم، ۵۰٪ یک هسته، ۱ گیگ دیسک، یک اسلات**. یک اسلات یعنی
  اپ و دیتابیس جدا نمی‌شود؛ برای همین ما SQLite را داخل همان پروسه داریم — به‌صرفه است.
- «۲۴/۷» یعنی بدون خواب زمان‌بندی‌شده و بدون تمدید دستی؛ **SLA ندارد**. ری‌استارت، خطا،
  به‌روزرسانی یا شلوغی می‌تواند سرویس را موقتاً پایین بیاورد.
- فضای ماندگار همان ۱ گیگ است؛ با `deploy/backup.sh` یا بکاپ پنل، یک نسخه همیشه **بیرون**
  از میزبان نگه دارید (`POST /api/...` لازم نیست، فایل SQLite را دانلود کنید).
- نصب وابستگی لازم نیست: پروژه هیچ dependency زمان اجرا ندارد.
