## چه چیزی اثبات می‌شود

| ادعا | چگونه |
|---|---|
| سقف ۲۰۰۰ op/دستگاه (D‑27) | ۱۸۰۰ ⇒ هشدار ۹۰٪ · ۲۰۰۰ ⇒ توقف پذیرش · ۲۰۰۱ ⇒ `queue_full` · **هیچ‌گاه حذف قدیمی** (F‑07) |
| اعمال idempotent | `UNIQUE(tenant_id, op_id)`؛ بازپخش همان `op_id` ⇒ همان نتیجه، بدون افزایش نسخه |
| ترتیب | `base_version` جلوتر ⇒ `409 ordering` و ماندن در `retry_wait` · عقب‌تر ⇒ `conflict` (نیازمند تصمیم) |
| دست‌نخوردگی بدنه | `payload_hash` ناهم‌خوان ⇒ `rejected` (امضا شاهد است، نه هویت — F‑06) |
| هویت فقط از نشست | `tenant_id` بدنه نادیده گرفته می‌شود؛ بدون نشست حتی با `sig` ⇒ ۴۰۱ |
| قاعدهٔ ۳۰ روز | op باز کهنه ⇒ `review`، **payload کامل حفظ**، ارسال خودکار متوقف؛ تعیین تکلیف فقط با دلیل ثبت‌شده در `queue_decision` |
| کش امن | AES‑256‑GCM، TTL ۷ روز، دست‌کاری ⇒ `tampered`، پایان نشست ⇒ پاک‌سازی، تغییر مدرسه ⇒ تخلیهٔ کامل |
| ساعت قابل اتکا (CC‑13‑۱) | پس از `sync` زمان با ساعت **یکنوا** پیش می‌رود ⇒ عقب‌بردن ساعت دستگاه TTL را تمدید نمی‌کند؛ `|offset| > ۱۰ دقیقه` ⇒ بدترین تفسیر |
| بازیابی کرش | ذخیره‌گاه پایدار؛ `sending` پس از کرش ⇒ `ack_unknown` (هرگز «موفق») |
| ابطال دستگاه (CC‑13‑۲/۳) | پنجرهٔ sync-on-revoke: آنلاین ⇒ `applied` و بدون `orphaned`؛ آفلاین ⇒ ردیف **`orphaned` سمت سرور** با `op_id`+`payload_hash`، سپس W2 (کلید نابود، payload غیرقابل خواندن، متادیتا برای حسابرسی می‌ماند) |

## چه چیزی اثبات **نمی‌شود**

اتصال به SQLite/محصول، UI آفلاین واقعی، WebCrypto غیرقابل‌استخراج روی دستگاه واقعی، سقف پلن،
همگام‌سازی چنددستگاهی و آزمون بار ۲۰۰۰ op روی شبکه — این‌ها ۱۹/۲۰‑ب هستند.
