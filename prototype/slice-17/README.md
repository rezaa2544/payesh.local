## چه چیزی اثبات می‌شود (AC مأموریت ۱۷)

| ادعا | چگونه |
|---|---|
| ورود درست/غلط، بدون افشای وجود کاربر | `/api/login` پاسخ ۴۰۱ یکسان برای «کاربر ناشناس» و «گذرواژهٔ غلط» |
| توکن دست‌کاری‌شده/منقضی/باطل‌شده رد می‌شود | HMAC + `token_hash` + `absolute/idle` + revoke |
| دسترسی مجاز/غیرمجاز بر پایهٔ نقش | ماتریس `policy.js` (Default Deny) و ۴۰۳ با دلیل ماشینی |
| دامنهٔ S0..S3 | مدیر کل مدرسه · دبیر کلاس خودش · ولی فرزند خودش · هنرجو ردیف خودش |
| **جداسازی tenant** | `tenant_id` فقط از نشست؛ کوئری/هدر/بدنهٔ جعلی نادیده گرفته می‌شود؛ خواندن/نوشتن متقابل ۰ ردیف/۴۰۴ |
| نقش‌های پلتفرم `—` روی دادهٔ مدرسه | `platform_support`: نمرات ۴۰۳، فرادادهٔ سلامت ۲۰۰ |
| رویدادنگاری | زنجیرهٔ `prev_hash/hash` و بررسی سلامت زنجیره |
| پنل نقش‌محور | منو از همان سیاست تولید می‌شود، نه فهرست دستی |

## چه چیزی اثبات **نمی‌شود**

RLS واقعی Postgres، اتصال به SQLite/محصول، `support_grant` (D‑21)، ثبت خواندن در
`support_access_log`، سیاست سقف پلن و حالت‌های `grace/suspended/expired` — این‌ها مأموریت‌های
۱۲‑ب/۱۶‑ب/۲۰‑ب هستند و در این نمونه **Runtime PASS** حساب نمی‌شوند.
