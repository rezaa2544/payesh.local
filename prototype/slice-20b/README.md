# نمونهٔ فنی ۲۰‑ب — آزمون چندمستأجری

آزمون اجرایی **معیار پذیرش ردیف ۲۰‑ب**: «نشت بین‌مدرسه‌ای، سقف پلن و حالت‌های اشتراک — با خروجی خام و SHA».
مبنا: `01b-school-plan-subscription.md` §۱.۱/§۲.۶ · `12b-owner-panel-boundaries.md` §۳.۳ · `16b-tenant-provisioning-migration.md` §۱.۱ · قانون اساسی §۴.۷/§۴.۹ · **D‑07 / D‑21 / D‑22 / D‑23 / D‑27**.

سیستم تحت آزمون: دروازهٔ نمونهٔ ۲۰ (`prototype/slice-20/lab.js` — هویت از توکن) روی هستهٔ تعارض نمونهٔ ۱۹، به‌علاوهٔ یک **لایهٔ پلتفرم** در `prototype/slice-20b/platform.js`:
سطح A (پنل پلتفرم) و سطح B (مدرسه)، سقف پلن در API، چرخهٔ اشتراک D‑22، مجوز اضطراری D‑21، و فضای ذخیره‌سازی بدون اعتبارنامهٔ پخته در کلاینت.

## اجرا

```bash
node prototype/slice-20b/tests/run.js      # ۷۱ ادعا — ۰ ناموفق لازم است (زیر ۰٫۲ ثانیه)
bash prototype/slice-20b/gen-evidence.sh   # شاهد خام: docs/cloud/reports/evidence/slice-20b-tenant-isolation.txt
```

`gen-evidence.sh` **fail‑closed** است: آزمون ناموفق، شمارش ناسازگار، کنترل منفی بی‌اثر، یا هر تغییر در مسیرهای محصول ⇒ شاهد سبز نوشته نمی‌شود.

## چه چیزی اثبات **نمی‌شود**

- **کد محصول همچنان تک‌مستأجری است (F‑05)**؛ این آزمون روی لایهٔ دادهٔ نمونه اجرا شده، نه روی endpointهای محصول. رفع F‑05 تغییر کد محصول است و به دروازهٔ فاز ۳ بستگی دارد.
- **RLS واقعی PostgreSQL** در مأموریت A‑02 جدا اجرا شده (۱۴/۱۴ PASS) و در این شاهد تکرار نشده است؛ این نمونه لایهٔ منطقی جداسازی را می‌سنجد.
- ظرفیت/کارایی (D‑11)، دسترس‌پذیری، و **Security Gate** (قانون اساسی §۱۰.۲) همچنان ادعانشده نیستند.
- سیاست‌های مالی (O‑15) و احراز هویت دومرحله‌ای پنل (O‑17) در دامنهٔ این نمونه نیستند.
