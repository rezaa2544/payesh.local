# نصب و به‌روزرسانی

این سند «چه چیزی را کجا نصب می‌کنیم» و «به‌روزرسانی چطور کار می‌کند» را عملی توضیح می‌دهد. خلاصهٔ دانلود در [README](../README.md) است.

---

## ۱. نقشهٔ کلی

```
                    ┌──────────────────────────────┐
                    │  سیستم دفتر مدرسه (ویندوز)   │
                    │  Node + SQLite + فایل‌های وب  │
                    │  http://192.168.x.x:8080     │
                    └───────────┬──────────────────┘
          Wi-Fi مدرسه          │           تونل HTTPS رایگان (اختیاری)
        ┌──────────────────────┼───────────────────────┐
        │                      │                       │
   📱 اندروید (APK/PWA)   📱 آیفون (PWA)          💻 دفتر (مرورگر)
```

- **فقط یک نسخه از داده** وجود دارد: روی سیستم مدرسه. گوشی‌ها فقط کش و صف دارند.
- هیچ هزینهٔ ماهانه‌ای ندارد؛ سرور، دامنه و پایگاه‌داده همه محلی‌اند.

## ۲. سیستم مدرسه (ویندوز)

| گام | کار |
|---|---|
| ۱ | دانلود `payesh-local-windows.zip` |
| ۲ | راست‌کلیک → Extract All |
| ۳ | دوبار کلیک روی `install.bat` |
| ۴ | در پایان، مرورگر با `http://localhost:8080` باز می‌شود |

نصب‌کننده چه می‌کند؟

1. وجود Node.js 22+ را بررسی می‌کند؛ اگر نبود با `winget` یا نصب‌کنندهٔ رسمی نصب می‌کند.
2. برنامه را در `C:\Payesh` می‌گذارد (داده‌ها در `C:\Payesh\data`).
3. یک وظیفهٔ زمان‌بندی (`PayeshLocal`) می‌سازد تا هر بار ویندوز روشن شد، سرور بی‌صدا اجرا شود.
4. قاعدهٔ فایروال برای پورت ۸۰۸۰ باز می‌کند (شبکهٔ خصوصی).
5. آیکون «پایش» را روی دسکتاپ می‌گذارد و مرورگر را باز می‌کند.

> ویندوز ممکن است هنگام اجرای `install.bat` هشدار SmartScreen بدهد؛ «More info → Run anyway».

**برداشتن نصب:** `powershell -ExecutionPolicy Bypass -File uninstall.ps1` (با `-Purge` داده‌ها هم حذف می‌شوند).

**لینوکس:** `sudo bash install/linux/install.sh` → سرویس `payesh.service` روی `/opt/payesh`.

## ۳. اندروید

دو راه، هر دو به یک برنامه می‌رسند:

**الف) APK (توصیه‌شده برای دبیران)**

1. `payesh-local.apk` را دانلود و نصب کنید («نصب از منابع ناشناس» را اجازه دهید).
2. برنامه را باز کنید — **هیچ آدرسی پرسیده نمی‌شود** و مستقیم وارد سامانه می‌شوید.

آدرس سرویس به‌ترتیب این منابع پیدا می‌شود (کاربر کاری انجام نمی‌دهد):

| ترتیب | منبع | کار مدیر |
|---|---|---|
| ۱ | آدرسی که قبلاً روی همان گوشی ذخیره شده | — |
| ۲ | آدرس **پخته‌شده در APK** (`PAYESH_APP_URL` هنگام بیلد یا `install/android/app/url.properties`) | یک‌بار تنظیم، همهٔ نصب‌ها خودکار |
| ۳ | فایل مرکزی [`android-config.json`](../android-config.json) در مخزن | یک خط `url` را پر کنید؛ **بدون ساخت دوبارهٔ APK** روی همهٔ گوشی‌ها اعمال می‌شود |
| ۴ | جستجوی خودکار سرویس در شبکهٔ Wi-Fi مدرسه (`http://<ip>:8080/api/health`) | — |
| ۵ | پرسیدن از کاربر (فقط اگر هیچ‌کدام پیدا نشد) | — |

اگر اتصال قطع شود، برنامه خودش هر ۲٫۵ ثانیه (تا ۶ بار) دوباره تلاش می‌کند و صفحهٔ «در حال اتصال» را نشان می‌دهد؛ نه پیام خطای خشک.

APK یک **پوستهٔ WebView** است: رابط کاربری همان PWA سرور است، بنابراین به‌روزرسانی برنامه فوراً و بدون نصب مجدد APK اعمال می‌شود.

**ب) PWA (بدون نصب فایل)**

آدرس سرور را در Chrome باز کنید → منوی سه‌نقطه → «نصب برنامه»/«افزودن به صفحهٔ اصلی».

## ۴. آیفون / آیپد

iOS اجازهٔ نصب APK ندارد و نصب PWA فقط روی **HTTPS** ممکن است:

1. آدرس HTTPS سرور (تونل) را در **Safari** باز کنید.
2. دکمهٔ اشتراک‌گذاری → «Add to Home Screen».
3. آیکون پایش اضافه می‌شود و تمام‌صفحه باز می‌شود.

اگر سرور فقط داخل شبکه است (`http://192.168...`)، آیفون می‌تواند از Safari استفاده کند ولی «افزودن به صفحهٔ اصلی» حالت اپ کامل نمی‌دهد. برای دسترسی از خانه، تونل را طبق [سند ۴](04-decisions-final-architecture.md) فعال کنید.

## ۴٫۵. آدرس عمومی ثابت — بدون آن، برنامه فقط داخل مدرسه کار می‌کند

هر کاربر اینترنت خودش را دارد؛ بنابراین آدرس `http://192.168.x.x:8080` فقط برای دستگاه‌هایی معنا دارد که به همان Wi-Fi وصل‌اند. برای همه — دبیر وسط حیاط با دادهٔ موبایل، ولی در خانه، دانش‌آموز در سفر — یک **آدرس HTTPS ثابت** لازم است:

```
https://payesh.<tailnet>.ts.net   ← تنها آدرس رسمی (Tailscale Funnel، رایگان)
```

### راه‌اندازی — از داخل خود برنامه، بدون خط فرمان

| گام | کار | چه اتفاقی می‌افتد |
|---|---|---|
| ۱ | نصب ویندوز با گزینهٔ «نصب Tailscale» (پیش‌فرض: تیک‌خورده) | `winget install Tailscale.Tailscale` (رایگان، حساب رایگان کافی است) |
| ۲ | پنل مدیر ← **شبکه** ← «فعال‌سازی آدرس عمومی» | سرور `tailscale funnel --bg 8080` را اجرا، آدرس `*.ts.net` را از خروجی می‌خواند و در پایگاه‌داده ذخیره می‌کند |
| ۳ | همان کارت: آدرس + **کپی** + **کد QR** | آدرس را برای اولیا/همکاران بفرستید؛ تمام |
| ۴ | (اختیاری) «تونل موقت» | Cloudflare quick tunnel: آدرس `https://<random>.trycloudflare.com` برای روزهای اضطراری (با ری‌استارت عوض می‌شود) |
| ۵ | «قطع دسترسی اینترنتی» | Funnel/تونل بسته و `public_url` پاک می‌شود؛ برنامه فقط داخل مدرسه باز می‌شود |

اگر Tailscale نصب نباشد، همان کارت دکمهٔ **«نصب Tailscale»** را نشان می‌دهد که صفحهٔ دانلود رسمی را باز می‌کند؛ اگر نصب باشد ولی وارد نشده باشد، دکمهٔ **«ورود به Tailscale»** پنجرهٔ ورود را باز می‌کند (سمت سرور `tailscale up` اجرا می‌شود).

> دامنهٔ اختصاصی دارید؟ فیلد «آدرس عمومی» را دستی پر کنید؛ برنامه آن را با برچسب `custom` ترجیح می‌دهد و تونل خودکار را خاموش نگه می‌دارد.

پس از فعال شدن:

- `GET /api/health` فیلد `public_url` را برمی‌گرداند و گوشی‌های اندروید خودکار همان را برمی‌دارند — **کاربر هیچ آدرسی تایپ نمی‌کند**.
- صفحهٔ «نصب» و پنل «شبکه» همان آدرس را با **کد QR** نشان می‌دهند.
- هر دستگاهی که با آدرس محلی وارد شده باشد، نوار زرد «این آدرس فقط داخل شبکه است» می‌بیند و با یک کلیک به آدرس رسمی منتقل می‌شود (نشست با کد انتقال یک‌بارمصرف منتقل می‌شود).
- سرور هر ۱۰ دقیقه وضعیت را تازه می‌کند و آدرس را در پایگاه‌داده/گزارش رویدادها نگه می‌دارد (`public_url_auto`).

### ویندوز: «برنامه» بودن حتی بعد از به‌روزرسانی

| موقعیت | چه اتفاقی می‌افتد |
|---|---|
| نصب تازه با `payesh-setup.exe` | میان‌بر `پایش.lnk` (دسکتاپ + منوی استارت) با هدف `wscript.exe payesh-app.vbs` ساخته می‌شود؛ کلیک = پنجرهٔ مستقل برنامه |
| نصب قدیمی + به‌روزرسانی یک‌کلیکی | `server/shortcut.js` شش ثانیه بعد از بالا آمدن سرور، `payesh-app.vbs`/`payesh.ico` را به ریشهٔ نصب می‌آورد و همان میان‌برها را بازنویسی می‌کند و `پایش.url` قدیمی را پاک می‌کند (یک‌بار برای هر نسخه) |
| باز شدن با مرورگر پیش‌فرض | فقط اگر Edge/Chrome نصب نباشد؛ در آن حالت هم صفحهٔ خطا نمی‌بینید چون سرور خودش روشن شده است |

اگر میان‌بر هنوز پنجرهٔ برنامه نمی‌دهد: `%LOCALAPPDATA%\Payesh\app` را پاک کنید و یک‌بار `C:\Payesh\payesh-app.vbs` را اجرا کنید.

### آزمون خودکار این مسیر

`npm run test:tunnel` دو ابزار جعلی (`tailscale`/`cloudflared`) می‌سازد و کل چرخه را می‌آزماید: تشخیص ابزار، فعال‌سازی Funnel، ذخیره و بازتاب آدرس در `health`/`network`، تونل موقت Cloudflare با regex آدرس، خاموش‌کردن، رد شدن نقش غیرمدیر، پیام «وارد نشده‌اید»، و حالت «هیچ ابزاری نصب نیست».

### نکته‌های امنیتی (چون سرور از اینترنت دیده می‌شود)

| کار | وضعیت |
|---|---|
| فقط HTTPS (Tailscale گواهی معتبر می‌دهد) | ✅ اجباری در تنظیمات |
| قفل موقت دستگاه پس از ۸ PIN اشتباه (۱۰ دقیقه، ذخیره‌شده در پایگاه‌داده) | ✅ |
| محدودیت نرخ ورود/راه‌اندازی به تفکیک IP واقعی (`X-Forwarded-For` فقط از تونل محلی) | ✅ |
| ابطال دستگاه گم‌شده از پنل مدیر | ✅ |
| گزارش ورودهای ناموفق در «گزارش رویدادها» | ✅ |

> اگر تونل قطع شود، برنامه روی گوشی‌ها از کش باز می‌شود و ثبت‌ها در صف می‌مانند؛ به‌محض برگشتن اینترنت، خودکار همگام می‌شوند.

## ۴٫۶. Hub ابری — وقتی سیستم مدرسه خاموش است

> این بخش اختیاری است و فقط اگر مدرسه بخواهد شب‌ها/تعطیلات هم دادهٔ تازه ببیند لازم می‌شود.

بدون Hub: گوشی‌ها از کش باز می‌شوند و درخواست‌ها در صف می‌مانند — ولی دادهٔ تازه تا روشن شدن سیستم مدرسه نمی‌رسد.
با Hub: مدرسه هر ۵ دقیقه (و هنگام هر همگام‌سازی) خلاصهٔ هر دانش‌آموز را به Cloudflare می‌فرستد؛ ولی از خانه همان خلاصه را می‌بیند و مرخصی‌اش در صف Hub می‌ماند تا مدرسه بکشد.

**استقرار (یک‌بار، ۱۰ دقیقه):**

```bash
cd hub
npx wrangler login
npx wrangler d1 create payesh_hub
# database_id را در wrangler.toml جای PASTE_D1_DATABASE_ID بگذارید
npx wrangler d1 execute payesh_hub --remote --file=schema.sql
npx wrangler secret put SCHOOL_KEY     # کلید را از پنل مدیر ← شبکه کپی کنید
npx wrangler deploy                    # آدرس workers.dev می‌گیرید
```

سپس در پنل مدیر ← «شبکه» ← بخش Hub: آدرس را وارد کنید، «فعال باشد» را بزنید و ذخیره کنید. دکمهٔ «همگام‌سازی اکنون» وضعیت را نشان می‌دهد.

| چه داده‌ای می‌رود؟ | چه داده‌ای نمی‌رود؟ |
|---|---|
| نام، کلاس، درصد حضور، ۲۰ نمرهٔ آخر، ۵ اطلاعیهٔ آخر | کد ملی، شمارهٔ تلفن، دادهٔ اولیای دیگر، پروندهٔ کامل |

- توکن هر خانواده با `HMAC(SCHOOL_KEY, "family:<id>")` ساخته می‌شود و Hub فقط `sha256` آن را ذخیره می‌کند؛ هر ولی فقط ردیف فرزند خودش را می‌گیرد.
- درخواست‌های مرخصی با `uid` یکتا ثبت می‌شوند؛ نه در Hub تکرار می‌شوند و نه در مدرسه.
- سقف رایگان Cloudflare (۱۰۰٬۰۰۰ درخواست در روز) برای ۴۵۰ دانش‌آموز با سینک تغییرات کافی است.

## ۵. به‌روزرسانی درجا — بدون دانلود دوبارهٔ برنامه

از نسخهٔ ۰٫۳٫۰ به بعد، هر تغییر در مخزن به‌صورت «آپدیت درجا» به مدرسه می‌رسد.
هیچ‌کس لازم نیست بستهٔ `.zip` را دوباره دانلود یا فایل‌ها را دستی جای‌گذاری کند.

### جریان کار

| گام | چه می‌شود |
|---|---|
| ۱ | CI روی `main` مانیفست را می‌سازد و `releases/manifest.json` را با کامیت `[skip ci]` در مخزن ثبت می‌کند |
| ۲ | سرور مدرسه هر ۳۰ دقیقه (و ۲۵ ثانیه پس از روشن شدن) مانیفست را از `raw.githubusercontent.com` می‌خواند؛ اگر نبود از `cdn.jsdelivr.net` و `fastly.jsdelivr.net` |
| ۳ | `sha256` هر فایل با نسخهٔ نصب‌شده مقایسه می‌شود؛ خروجی: فهرست کوتاه فایل‌های تغییرکرده + حجم |
| ۴ | مدیر در پنل، نوار «🎁 نسخهٔ X منتشر شده — فقط N فایل تغییر کرده (KB)» را می‌بیند |
| ۵ | با یک کلیک فقط همان فایل‌ها دانلود، هش‌بررسی و جای‌گذاری می‌شوند |
| ۶ | اگر یکی از فایل‌ها `server/…` باشد، سرور خودش دوباره راه می‌افتد (۳۵۰ms بعد از پاسخ)؛ وگرنه هیچ وقفه‌ای نیست |
| ۷ | گوشی‌ها/مرورگرها در بازدید بعدی، دلتای کلاینت را از `sw.js` می‌گیرند |

### امنیت و بازگشت

- **اتمی:** همهٔ فایل‌ها اول در `data/updates/<نسخه>/` دانلود و هش‌بررسی می‌شوند؛ اگر یکی ناسازگار باشد **هیچ فایلی** نوشته نمی‌شود.
- **محدودهٔ نوشتن:** فقط `client/`، `server/`، `hub/`، `docs/`، `package.json`، `start.bat`، `start.sh`. مسیرهایی مثل `../`، `data/…`، `C:\…` رد می‌شوند (`isUpdatable`).
- **پشتیبان:** فایل‌های جای‌گذاری‌شده در `data/backups/update-<نسخه>/` کپی می‌شوند؛ دکمهٔ «بازگشت به نسخهٔ قبل» همین را برمی‌گرداند.
- **داده:** پوشهٔ `data/` جز پوشه‌های آپدیت/بکاپ هیچ‌وقت نوشته نمی‌شود.
- **دسترسی:** همهٔ مسیرهای `/api/admin/update/*` فقط برای نقش `manager`.

### API

```
GET  /api/admin/update                  وضعیت کامل (نسخهٔ در حال اجرا، طرح، آخرین نصب، تنظیمات)
POST /api/admin/update/check  {force}   مقایسهٔ تازه با مخزن
POST /api/admin/update/apply            دانلود و نصب دلتا
POST /api/admin/update/rollback         بازگشت به نسخهٔ قبل
POST /api/admin/update/settings {auto, auto_apply, base}
POST /api/admin/update/restart          راه‌اندازی مجدد دستی
GET  /api/update/check?current=<ver>    دلتای کلاینت (برای Service Worker)
GET  /api/health                        version (در حال اجرا) · installed_version · restart_pending
```

نمونهٔ پاسخ `/api/admin/update/check`:

```json
{ "ok": true, "plan": {
  "ok": true, "available": true,
  "local_version": "0.3.0", "remote_version": "0.3.1",
  "changed": [{ "path": "client/app.js", "kind": "client", "sha256": "…", "size": 28743 }],
  "removed": [], "counts": { "changed": 1, "client": 1, "server": 0, "removed": 0 },
  "total_size": 28743, "needs_restart": false,
  "source": "https://raw.githubusercontent.com/…/main/"
}}
```

### تنظیمات (پنل مدیر ← سیستم ← به‌روزرسانی)

| گزینه | پیش‌فرض | کار |
|---|---|---|
| بررسی خودکار | روشن | هر ۳۰ دقیقه مخزن را نگاه می‌کند و نوار اعلان نشان می‌دهد |
| نصب خودکار بدون پرسش | خاموش | خودش دلتا را می‌گیرد و (در صورت نیاز) سرور را دوباره راه می‌اندازد |
| منبع آپدیت | خالی (آینه‌های پیش‌فرض) | اگر مدرسه به GitHub دسترسی ندارد، آینهٔ خودش (مثل Worker ابری) را بگذارد |

متغیرهای محیطی معادل: `PAYESH_UPDATE_BASE`، `PAYESH_UPDATE_AUTO=0`، `PAYESH_NO_RESTART=1`، `PAYESH_APP_ROOT`.

### ساخت نسخهٔ جدید (برای مدیر سیستم)

```bash
npm version patch          # شمارهٔ نسخه بالا برود (وگرنه بیلد قبول نمی‌کند)
npm run build:release      # mانیفست + بستهٔ ویندوز + tar.gz
git add -A && git commit -m "chore: نسخهٔ X" && git push origin main
```

CI تست‌ها را می‌زند، مانیفست تازه را با `[skip ci]` روی `main` ثبت می‌کند و بسته‌ها را در انتشار `continuous` می‌گذارد.
از آن لحظه، همهٔ مدرسه‌ها در بررسی بعدی، آپدیت را می‌بینند.

### آزمون

```bash
npm run test:update   # ۱۰ آزمون: دلتا، اتمی بودن، هش ناجور، بازگشت، دسترسی، مسیر ناامن
```

## ۶. پشتیبان‌گیری

- هر شب (پیش‌فرض) یک فایل `.sqlite` در `data/backups` ساخته می‌شود و ۳۰ نسخهٔ آخر نگه داشته می‌شود.
- از پنل مدیر ← «پشتیبان‌گیری» می‌توانید همین حالا نسخه بسازید و دانلود کنید.
- برای آرشیو بیرون از مدرسه: فایل پشتیبان را در فضای ابری رایگان (Terabox/گوگل‌درایو) بگذارید؛ این کار عمداً **دستی** است تا دادهٔ دانش‌آموزان بدون اجازهٔ مدیر جایی نرود. برای خودکارسازی می‌توانید `rclone` را روی همان سیستم تنظیم کنید (راهنما در سند ۴).

## ۷. رفع اشکال‌های رایج

| نشانه | علت احتمالی | راه‌حل |
|---|---|---|
| گوشی «اتصال برقرار نشد» می‌دهد | گوشی روی Wi-Fi مهمان است یا سیستم خواب رفته | Wi-Fi مدرسه را انتخاب و «بهبود شبکهٔ خصوصی» را روشن کنید؛ در ویندوز Sleep را غیرفعال کنید |
| صفحهٔ وب باز می‌شود ولی نصب روی آیفون نیست | آدرس `http` است | تونل HTTPS را فعال کنید |
| بعد از آپدیت، نسخهٔ قدیمی می‌ماند | Service Worker هنوز فعال نشده | یک‌بار بستن و باز کردن اپ، یا «بررسی به‌روزرسانی» در صفحهٔ سیستم |
| «دستگاه نامعتبر» | نشست منقضی شده | دوباره PIN بزنید؛ اگر نشد کارت پیوند جدید از دفتر بگیرید |
| پورت ۸۰۸۰ اشغال است | برنامهٔ دیگری روی آن است | `PORT=8081` را در `start.bat` یا متغیر محیطی تنظیم کنید |
