# مدل اجرایی بار و هزینهٔ دیتابیس — ردیف ۳۳

| | |
|---|---|
| ردیف | ۳۳ (فاز ۲) |
| وضعیت | **اجراشده** — ابزار اجرایی + آزمون خودکار + شاهد خام |
| ابزار | `tools/cost-model.cjs` + دفترچهٔ فرض `tools/price-book.json` |
| آزمون | `npm run test:model` ⇒ ۱۰ موفق · ۰ ناموفق |
| شاهد | `docs/cloud/reports/evidence/phase2-decisions.txt` |

برچسب اعداد: **[M]** اندازه‌گیری‌شده در همین مخزن · **[A]** فرض مهندسی · **[E]** برآورد قیمت · **[?]** نامعلوم.
**همهٔ اعداد این مدل تا اندازه‌گیری ردیف ۴۶ [A] هستند**، به‌جز آن‌هایی که صریحاً [M] علامت خورده‌اند.

---

## ۱. ورودی‌ها (قابل تغییر روی خط فرمان)

| ورودی | پیش‌فرض | برچسب | معنا |
|---|---|---|---|
| `schools` | از پله (۱۰ / ۱۰۰ / ۱۰۰۰) | [A] | تعداد مدرسه |
| `users` (per school) | ۱۲۰ / ۲۰۰ / ۲۵۰ | [A] | کاربر ثبت‌شده در هر مدرسه |
| `syncs` | ۴۰ بر دستگاه در روز | [A] | همگام‌سازی روزانه هر دستگاه |
| `row-bytes` | ۴۲۰ | [M] | دادهٔ خالص هر ردیف (۲۹۱MB / ۳۳۴٬۶۴۷ ردیف) |
| `peak` | ۴× | [A] | نسبت اوج به میانگین |

## ۲. فرمول‌ها (همان چیزی که کد اجرا می‌کند)

```
devices      = users × device_ratio(0.35)                       [A]
requests/day = devices × syncs_per_device_per_day(40)           [A]
RPS_avg      = requests/day ÷ 86400
RPS_peak     = RPS_avg × peak_factor(4)
concurrent   = RPS_peak × avg_latency(120ms)                    (قانون لیتل: [M]+[A])
rows_year1   = schools × rows_per_school(83,700)                [M]
bytes/row    = row_bytes × index_overhead(1.18)                 [M]
GB_year1     = rows_year1 × bytes/row ÷ 1e9
GB_year4     = GB_year1 × (1 + 0.3×3)                           [A: رشد ۳۰٪ سالانه]
vcpu         = ceil(RPS_peak ÷ 75 × 1.5)                        [M: ۱۵۰RPS روی ۲vCPU، حاشیهٔ ۱.۵×]
ram_gb       = ceil(concurrent ÷ 100 × 2)                       [A]
€/ماه خودمیزبان = vcpu×0.026×730 + ram×0.0044×730 + GB×0.10 + GB×0.03   [E]
€/ماه مدیریت‌شده = پلهٔ ۲۵ / ۷۰ / ۱۸۰ بر اساس vcpu                [E]
```

## ۳. خروجی واقعی (اجرای همین مخزن)

```
پله            مدرسه  کاربر  دستگاه  RPS میانگین  RPS اوج  اتصال هم‌زمان  ذخیره‌سازی(GB سال۱/سال۴)  vCPU/RAM  خودمیزبان €/ماه  مدیریت‌شده €/ماه
T1 — پایلوت        10    1200      420         0.19      0.78           0.09            0.41 / 0.79   1 / 1GB            22.29                25
T2 — شهر          100   20000     7000         3.24     12.96           1.56            4.15 / 7.88   1 / 1GB            23.22                25
T3 — استان       1000  250000    87500        40.51    162.04          19.44          41.48 / 78.82   4 / 1GB            89.38               180
```

خواندن این جدول:
- تا **۱۰۰ مدرسه** یک نمونهٔ کوچک (۱ vCPU) با حاشیهٔ زیاد کافی است؛ اوج ۱۳ RPS در برابر سقف اندازه‌گیری‌شدهٔ ۱۵۰ RPS [M].
- در **۱۰۰۰ مدرسه** اوج ۱۶۲ RPS از سقف یک نمونهٔ ۲vCPU (۱۵۰ RPS [M]) می‌گذرد ⇒ ۴ vCPU + بازبینی replica.
- ذخیره‌سازی ۱۰۰۰ مدرسه در سال چهارم ≈۷۹GB [A] — یعنی هزینهٔ دیسک در برابر هزینهٔ vCPU کوچک است.

## ۴. اجرا

```bash
node tools/cost-model.cjs                       # جدول خوانا
node tools/cost-model.cjs --json                # خروجی ماشین‌خوان
node tools/cost-model.cjs --schools 500 --peak 6 --json
npm run test:model                              # ۱۰ آزمون صحت فرمول/یکنوایی/کنترل منفی
```

## ۵. محدودیت‌های صریح

1. همهٔ هزینه‌ها **[E]** هستند: قیمت بازار، نه پیشنهاد رسمی هیچ ارائه‌دهنده‌ای. پیش از خرید باید تأیید شود.
2. سنجش ظرفیت روی **یک میزبان ۲vCPU/۴GB** انجام شده؛ هیچ ادعای HA/SLA نیست.
3. مدل، بار شبکه/CDN و هزینهٔ ترافیک را حساب نمی‌کند ([?] تا سنجش ردیف ۴۶).
4. `ram_gb` ساده‌سازی‌شده است ([A])؛ مصرف واقعی حافظه با ۱۰۰۰ مدرسه اندازه‌گیری نشده [?].
