# ردیف ۸۲: آزمون بار و اندازه‌گیری روی Gateway + PostgreSQL

> تاریخ: ۱۴۰۵/۰۸/۲۰ (2026-11-11) · مجری: ARENA (ابزار + CI) · OWNER: اجرا روی دیتابیس مدیریت‌شده (T2)

## ۱. قانون برچسب‌گذاری

- **[S]**: شبیه‌سازی روی ماشین توسعه یا runner CI (loopback، دستگاه‌های مصنوعی). **همهٔ** اعداد این ردیف [S] هستند.
- برچسب سنجیده‌شده روی **هدف واقعی** (دیتابیس مدیریت‌شدهٔ مالک، T2) فقط با `PAYESH_T2_MANAGED_DB=1` پذیرفته می‌شود. این کار فقط از OWNER برمی‌آید و CI هرگز آن را تنظیم نمی‌کند. ابزار بدون آن با کد خروج ۲ رد می‌کند (LD-02).
- **ادعای «نامحدود» ممنوع است.** گزارشی که این واژه یا معادل‌هایش را داشته باشد رد می‌شود (`claimsGate`، LD-02). عددهای این سند فقط همین اجرا را توصیف می‌کنند، نه ظرفیت تولید را.

## ۲. ابزار

| بخش | فایل |
|---|---|
| اسکریپت بار (بی‌وابستگی، به سبک autocannon) | `tools/load-82.mjs` |
| آزمون و دروازه | `tests/load-82.js` (`npm run test:load82`) |
| تزریق خطا، فقط برای کنترل منفی | `tests/fixtures/load-82-inject.cjs` |
| CI | `api-contract.yml`، گام «Load test (row 82)» روی سرویس `postgres:16` با `LOAD82_REQUIRE_PG=1` و گزارش خام `load-82-report.json` به‌صورت artifact |

هر دستگاه مجازی token، `X-Device-Id` و مکان‌نمای pull (`since_seq`) خودش را دارد. ترکیب درخواست‌ها ۸۰٪ pull و ۲۰٪ push است (۱ تا ۳ op). بار به‌صورت closed-loop با N کارگر هم‌زمان روی اتصال keep-alive فرستاده می‌شود. حافظهٔ RSS فرایند Gateway هر ثانیه از `/proc/<pid>/status` نمونه‌برداری می‌شود.

## ۳. دروازه‌ها (منبع: `deploy/monitoring/slo-85.yml`)

| دروازه | آستانه |
|---|---|
| نرخ خطا (هر پاسخ غیر 200) | ≤ ۰٫۵٪، بودجهٔ خطای SLO دسترس‌پذیری ۹۹٫۵٪ |
| p95 تأخیر | ≤ ۱۰۰۰ ms، همان SLO تأخیر |
| نشت حافظه | شیب RSS > ۳۰ MB/min **و** رشد میانگین ثلث آخر نسبت به ثلث اول > ۲۴ MB ⇒ قرمز |
| برچسب و ادعا | همهٔ بخش‌ها برچسب دارند و هیچ ادعای نامحدودی نیست |

## ۴. نتیجهٔ اجرای اصلی [S]

پیکربندی: ۲٬۰۰۰ دستگاه، ۲۰ مدرسه، ۶۴ هم‌زمان، ۳۰ ثانیه پس از ۵ ثانیه گرم‌کردن. اعداد دقیق در `docs/cloud/reports/evidence/load-82.txt` و گزارش خام `load-82-report.json` آمده‌اند:

- [S] حدود ۱۸ هزار درخواست با حدود ۶۰۰ درخواست در ثانیه.
- [S] تأخیر p50/p95/p99 حدود ۱۰۴/۱۳۵/۱۵۵ ms.
- [S] صفر خطا.
- [S] RSS از حدود ۸۲ به ۸۷ MB رسید، بدون نشانهٔ نشت.

این عددها روی **یک** فرایند Gateway و PostgreSQL محلیِ کوچک (embedded، `shared_buffers=16MB`) به دست آمده‌اند. روی runner CI با `postgres:16` عددها متفاوت‌اند و هر اجرا گزارش خام خودش را دارد.

## ۵. کنترل‌های منفی (روی فرایند واقعی Gateway)

| تزریق | دروازهٔ قرمزشده |
|---|---|
| نگه‌داشتن ۶۴ KB به‌ازای هر درخواست (نشت) | memory_leak |
| `PAYESH_FEATURE_KILL=push` (پاسخ 503) | error_rate |
| تأخیر ۱٫۲ ثانیه پیش از هر درخواست | p95 |
| ادعای «unlimited» یا «نامحدود»، نبود برچسب، برچسب هدف واقعی بدون دیتابیس مدیریت‌شده | claims |

LD-08 کنترل مثبت است: همان پروفایل کوتاه روی Gateway دست‌نخورده سبز می‌ماند. پس قرمز شدن کنترل‌های منفی از تزریق است، نه از خود پروفایل.

## ۶. اجرای OWNER روی T2 (خارج از ARENA)

```
PAYESH_T2_MANAGED_DB=1 node tools/load-82.mjs --base https://<gateway> --secret "$GW_SECRET" \
  --gw-pid <pid روی میزبان Gateway> --devices 2000 --tenants 20 --duration 300 --concurrency 64 \
  --label M --out load-82-T2.json
```

فقط خروجی همین اجرا روی دیتابیس مدیریت‌شده برچسب هدف واقعی می‌گیرد. حذف `--gw-pid` اندازه‌گیری حافظه را خاموش می‌کند و این موضوع در گزارش ثبت می‌شود.
