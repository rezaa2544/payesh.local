## ۲. سه نقص یکپارچگی که باید پیش از هر چیز رفع شوند

### F‑07 — حذف بی‌صدای عملیات در سقف ۵۰۰
```js
// client/app.js:121
function saveQueue() { localStorage.setItem('payesh.queue', JSON.stringify(S.queue.slice(-500))); }
```
بدون هیچ پیام، بدون ثبت، بدون «نیازمند بررسی». اگر معلمی در یک هفتهٔ آفلاین ۵۱۰ حضور ثبت کند، **۱۰ ثبت اول برای همیشه می‌رود**. این مستقیماً بند ۸ قانون اساسی («هیچ‌چیز گم نمی‌شود») و D‑27 را نقض می‌کند.
**الزام رفع:** سقف ۲۰۰۰ + مسدودسازی افزودن در سقف (بدون حذف) + وضعیت صریح «نیازمند بررسی» پس از ۳۰ روز + هشدار در ۸۰٪.

### F‑08 — تعارض = «سرور برنده» (نقض D‑28)
```js
// client/app.js:335-339
S.queue = S.queue.filter(op => op.uid !== c.uid && !(…same record…));
toast('تعارض در N رکورد — نسخهٔ سرور اعمال شد', 'err');
```
کار کاربر (نسخهٔ محلی) دور ریخته می‌شود. در D‑28 تصویب شد: **هر دو نسخه حفظ، تشخیص با `base_version`، حل فقط با نقش مجاز + ثبت تصمیم**. امروز هیچ‌کدام نیست.

### F‑09 — رد شدن، دور ریختن است
`rejected` (مثلاً «سقف پلن پر است» یا «خارج از محدوده») موجب حذف op می‌شود. در سناریوی ۰۱‑ب §۵.۲، op ردشده باید **با دلیل** بماند تا کاربر ببیند و اصلاح کند.
