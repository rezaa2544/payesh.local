# ردیف ۴۲ — هزینهٔ همگام‌سازی: سقف درخواست و بایت به‌ازای هر کاربر در روز

**وضعیت:** پیاده‌سازی + اندازه‌گیری واقعی + دروازهٔ CI
**کد:** `server/sync.js` (ETag)، `server/index.js` (۳۰۴ روی `/api/v1/pull`)،
`client/app.js` (conditional GET + زمان‌بند تطبیقی)، `client/sync-schedule.js` (سیاست)،
`client/outbox-web.js` (jitter عقب‌نشینی)، `tools/sync-budget.json` + `tools/sync-budget-42.cjs` (آستانه)
**آزمون:** `tests/sync-cost-42.js` — ۱۵ کنترل (SC‑01..SC‑15) · `npm run test:cost42`
**شاهد خام:** `docs/cloud/reports/evidence/sync-cost-42.txt` (+ `.json`)

---

## ۱) مسئله

نسخهٔ قبل: کلاینت هر **۱ ثانیه** `liveTick` می‌زد (تایمر ثابت) و هر **۹۰ ثانیه** pull کامل
می‌گرفت، بدون هیچ شرطی؛ صندوقچه هم در خطا فقط `base * 2^n` عقب می‌رفت (بدون تصادف).
یعنی:

* pull تکراری همیشه بدنهٔ کامل برمی‌گرداند (حتی وقتی هیچ چیز عوض نشده)،
* هر دستگاه در بازگشت اینترنت **هم‌زمان** با بقیه به سرور هجوم می‌آورد،
* هیچ سقفِ عددی و هیچ دروازه‌ای در CI وجود نداشت که «هزینهٔ روزانهٔ هر کاربر» را ببندد.

### ۲.۱) چرا ETag به مکان‌نما مقید است (و ۳۰۴ کاذب ممکن نیست)

ETag از `(since, since_id, more, next_since, next_id, collections, deleted)` ساخته می‌شود.
پس اگر مکان‌نمای کلاینت با مکان‌نمای سازندهٔ ETag یکی نباشد، پاسخ **۲۰۰** است، حتی اگر
داده‌ای عوض نشده باشد. کنترل SC‑04 همین را می‌سنجد: ETag کهنه + مکان‌نمای تازه ⇒ ۲۰۰،
و ETag کهنه + همان مکان‌نما ولی دادهٔ تغییریافته ⇒ ۲۰۰ (نه ۳۰۴).
یعنی ۳۰۴ فقط و فقط وقتی صادر می‌شود که «همان بدنهٔ قبلی» دوباره تولید شود.

### ۲.۲) جیتر — بدون شکستن قرارداد ردیف ۴۰

`next_at` قبلاً دقیقاً `now + baseBackoffMs` بود و `tests/outbox-40.js` (OB‑07) همین را
assert می‌کرد. حالا:
`next_at = now + round(base * factor)`, `factor ∈ [1−j, 1]`, `j = DEFAULTS.jitter = 0.5`.
OB‑07 به‌جای «تساوی قطعی» بازهٔ `[now + 0.5·base, now + base]` را می‌سنجد — **تنگ‌تر از
حذف کنترل نیست، ولی دیگر رفتار تصادفی را رد نمی‌کند**. SC‑07 نشان می‌دهد ۴۰ تلاش ⇒
`range=501..991 ms`، `unique=39/40` (پس واقعاً تصادفی است، نه ثابت).

| سنجه | مقدار |
|---|---|
| پاسخ ۳۰۴ (بدنه ۰) | **615 B** |
| pull خالی ۲۰۰ (بدنهٔ JSON کوچک) | 967 B |
| pull با ۱۳۲ ردیف | 17,946 B |
| push دسته‌ای ۱۲۰ عملیات (آپلود) | 19,737 B |

مدل روزانه (۲۴ ساعت) و سقف:

| سناریو | درخواست/روز | سقف | بایت/روز | سقف |
|---|---|---|---|---|
| دستگاه باز و بی‌کار (visible, idle) | **588** | 900 | **353 KB** | 768 KB |
| پس‌زمینه/آفلاین | **96** | 200 | 58 KB | 128 KB |
| معلم فعال (۶۰ push دسته‌ای) | **648** | 1200 | 3.8 MB | 8 MB |

کاهش در مقیاس: `86,400` کاوش در روز (۱ ثانیه‌ای ثابت) ⇒ **۵۸۸** کاوش (۰.۷٪)، و

**N = 1 مدرسه، ۱ device، اندازه‌گیری محلی. مقیاس چندمدرسه‌ای ضرب خطی همین مدل است، نه اندازه‌گیرى‌شده.**

## ۴.۱) قید «هر ۱ ثانیه» کجا حفظ شد و کجا نه

قید صریح محصول «تازه‌سازی ۱ ثانیه‌ای» است. سیاست جدید آن را در جایی که معنا دارد
**دقیقاً حفظ می‌کند** و فقط در بی‌کاریِ کامل شل می‌شود:

| وضعیت | فاصلهٔ کاوش |
|---|---|
| داده در حال تغییر است (هر پاسخ تازه چیزی برگرداند) | **۱ ثانیه** |
| کاربر در تعامل است (کلیک/کلید/لمس — `liveTouch`) | **۱ ثانیه** |
| بازگشت به برنامه / بازگشت اینترنت | بلافاصله (۰..۲s تصادفی) |
| ۱۰ ثانیه بی‌تغییر و بی‌تعامل | ۱.۶× → ۶۰ ثانیه |
| ~۳ دقیقه بی‌کاری | ۱۸۰ ثانیه |
| ~۵ دقیقه بی‌کاری | ۳۰۰ ثانیه |
| تب در پس‌زمینه | **صفر** (فقط جاروی ۱۵ دقیقه‌ای) |

یعنی «۱ ثانیه» به‌عنوان قرارداد کاربر در همهٔ حالت‌هایی که کاربر واقعاً منتظر تازگی است
برقرار است؛ آنچه حذف شد، poll یک‌ثانیه‌ایِ **دستگاهی که کسی پشتش نیست** است — همان چیزی
که بودجهٔ ردیف ۴۲ را می‌شکست.

## ۵) دامنهٔ صادقانه (چه چیزی ثابت نشده)

* این اعداد **مدل + اندازه‌گیری محلی** روی یک دستگاه Node هستند؛ ترافیک واقعی کاربران
  در میدان (اپراتور موبایل، پراکسی، retry شبکه) اندازه‌گیری نشده است.
* ۶۱۵ بایتِ هر ۳۰۴ تقریباً همه‌اش **هدر** است (CORS + سرآیندهای امنیتی سراسری). برای
  کوچک‌ترکردن آن باید در لایهٔ پروکسی/CDN یا با long-poll کار شود؛ در این ردیف انجام نشد.
* nginx/HTTP2/keep-alive در این اندازه‌گیری دخیل نیست (`agent=false`, `connection: close`).
  با keep-alive اعداد بایت **کمتر** می‌شود، ولی اینجا محافظه‌کارانه اندازه‌گیری شده.
* «سقف» یک **سیاست** است، نه واقعیتِ فیزیکی؛ اگر ویژگی تازه‌ای هر ثانیه poll بزند،
  دروازه قرمز می‌شود و باید آگاهانه سقف را بازنگری کرد — همان چیزی که `tools/sync-budget.json` می‌گوید.
