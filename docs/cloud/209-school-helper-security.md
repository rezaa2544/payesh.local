# ردیف ۲۰۹ — عضویت مدارس به‌عنوان Helper: توکن و بازبینی امنیتی (DP-4)

## سازوکار
- کلید صندوقچه **هرگز** به مدرسه داده نمی‌شود (وضعیت فعلی عمدی است: فقط پنل مالک).
- مالک برای هر مدرسه توکن مشتق صادر می‌کند: ‏`<school_id>.<b64u(HMAC-SHA256(bucketSecret,"payesh/school-helper:<id>"))>` — ‏`helper-v2.schoolToken/verifySchoolToken` (Node) و `schoolHelperToken/verifySchoolHelperToken` (Dart، `helper_box.dart`) بایت‌به‌بایت هم‌معنا.
- helper مدرسه با ‏`cls=school` و `school_id` خودش حضور می‌زند؛ `canLease`: فقط کار همان مدرسه یا نوع‌کار `public`؛ ‏`school-content` بیگانه هرگز.
- ابطال: حذف/چرخش در پنل مالک (چرخش سکرت صندوقچه همهٔ توکن‌ها را باطل می‌کند؛ ابطال تکی با فهرست ابطال در سیاست زیرساخت، کار آیندهٔ پنل).

## مدل تهدید
| تهدید | پاسخ |
|---|---|
| توکن دزدیده‌شده | فقط کار همان school_id + public؛ بدون کلید صندوقچه نتیجهٔ جعلی ممکن نیست (GCM)؛ ابطال با چرخش |
| مدرسهٔ متخاصم | canLease دوطرفه (فرستنده و executor)؛ کار مدرسهٔ دیگر رد می‌شود — تست DP-211 |
| نتیجهٔ جعلی | برچسب AES-GCM؛ کلید دیگر ⇒ open_failed |
| اجارهٔ رها‌شده | انقضای ۶۰ ثانیه؛ برداشت دیگری یا محلی |

## مرز صادقانهٔ این ردیف
هستهٔ توکن + داوری دسترسی + تست متقابل دو مدرسه پیاده شد. دکمهٔ «صدور توکن» در UI پنل مالک و فهرست ابطال تکی هنوز سیم‌کشی نشده و باید در یک ردیف UI جدا بیاید؛ تا آن زمان صدور با ابزار مالک و همان تابع انجام می‌شود.
