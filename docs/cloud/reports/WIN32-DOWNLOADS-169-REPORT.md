# ردیف ۱۶۹ — نسخهٔ ۳۲ بیتی همهٔ نصب‌کننده‌های ویندوز + صفحهٔ دانلود دسته‌بندی‌شده (v0.9.24)

**درخواست مالک:** «همه فایل های نصبی ویندوز باید ورژن 32 بیتی رو هم داشته باشن. لطفا لینک دانلودهارو در صفحه گیت هاب منظم بچین و همه لینک هارو دسته بندی کن»

**انتخاب‌های مالک (پاسخ به پرسش):**
- نسخهٔ ۳۲ بیتی **کامل**، از همان کد و با همان ظاهر (نه پوستهٔ سبک پنل وب).
- لینک‌ها هم در README دسته‌بندی شوند و هم در انتشار سنجاق‌شدهٔ «⬇️ دانلودها» در صفحهٔ Releases.
- فایل‌های فقط-به‌روزرسانی برچسب «دستی دانلود نکنید» بگیرند.

## علت و تصمیم (D‑50، ADR‑169)
- Flutter موتور ویندوز ۳۲ بیتی ندارد (Dart #45222 و #59698). برای همین اپ مدرسه و پنل مالک فقط `exe` ۶۴ بیتی داشتند.
- سرور دیتابیس مدرسه از قبل یک نصب‌کنندهٔ مشترک ۳۲ و ۶۴ بیتی داشت.
- **راه‌حل:** همان کد Flutter با `flutter build web` به JavaScript ترجمه می‌شود و در یک برنامهٔ ۳۲ بیتی Chromium 109 (CEF) اجرا می‌شود. Chromium 109 آخرین نسخهٔ سازگار با ویندوز ۷ است. برنامه در `tools/web32/shell` است.
  - برنامهٔ میزبان، کارهایی را که `dart:io` در نسخهٔ ۶۴ بیتی انجام می‌دهد از راه `window.payeshHost` در اختیار اپ می‌گذارد: فایل، DPAPI، پردازه و DNS.
  - دیتابیس همان SQLite3MC رمزنگاری‌شده است (ChaCha20، wasm)، روی همان فایل `%LOCALAPPDATA%\Payesh\payesh.db`. دیتابیسی که SQLite3MC بومی ساخته، در نسخهٔ وب باز می‌شود (`WEB32-SQLITE-OK 6`).
- **این نسخه بومی خوانده نمی‌شود.** D‑49 دست نخورده و کانال‌های بومی فقط بومی ماندند.
  - رجیستری نوع تازهٔ `web32-compat` دارد و قاعدهٔ I‑12 مرزهایش را نگه می‌دارد، با ۵ جهش: فقط `windows-x86`، فقط `policy: D-50`، پرچم‌های صادق، همان `lib/` دوقلوی بومی، فقط کانال `win32-continuous` و دروازهٔ web32 روی همان فایل منتشرشده.
  - قانون اساسی ۱٫۱۹ با D‑50؛ ADR: `docs/cloud/169-adr-web32-compat.md`.

## CI و انتشار
- **`win32-edition.yml`:**
  1. بررسی سازگاری: `WEB32-IO-OK 16` و `WEB32-SQLITE-OK 6`.
  2. ساخت وب اپ مدرسه و پنل مالک.
  3. ساخت برنامهٔ ۳۲ بیتی با MSVC (`-A Win32`، `/MT`) روی CEF با sha1 ثابت.
  4. دروازهٔ `web32-gate.mjs` روی پوشه و zip: PE ‏0x014c، runtime کامل، بدون node.exe و WebView2.
  5. ساخت Inno.
  6. نصب بی‌صدا، سپس `e2e.mjs` روی **برنامهٔ نصب‌شده** (۹ بررسی برای اپ، ۸ بررسی برای پنل): قرارداد میزبان، fetch به LAN بدون سرآیند CORS، https با ریشه‌های Chromium، رد `window.open`، رندر Flutter، دیتابیس رمزنگاری‌شده و خروج. در پایان حذف نصب.
- **`win32-publish.yml`:** فقط پس از اجرای سبز روی main اجرا می‌شود. همهٔ نشانگرها، sha256، دروازه و مانیفست‌ها را دوباره بررسی می‌کند. پس از بارگذاری، فایل‌ها دوباره دانلود و بررسی می‌شوند (`WIN32-PUBLISH-OK 7`).
- **CI سبز روی `b5fb4d4`:** win32-edition #7، win32-publish، build-and-release، installables-registry و downloads-page. native-client روی `ae6ea2e` هم سبز است.
- **آزمون‌ها:** npm ‏150/150؛ app 225، owner 281، sync 287، secure 52، update 22، data 28، core 16، owner_api 20؛ installables-125 با ۳۹ جهش، downloads-169 با ۱۶ بررسی و ۱۱ جهش، adr-117 با ۱۱ جهش.

## اشکال‌هایی که در CI و روی رایانه پیدا و رفع شد
1. مسیر ویندوزی `CEF_ROOT` در cmake: تبدیل با `file(TO_CMAKE_PATH)`.
2. `MachineGuid` از پردازهٔ ۳۲ بیتی روی ویندوز ۶۴ بیتی در نمای WOW6432Node نیست. اپ از `/reg:64` استفاده می‌کند و اگر جواب نداد، پرس‌وجوی ساده را امتحان می‌کند.
3. سرور مدرسه سرآیند CORS نمی‌فرستد. CORS در برنامهٔ قفل‌شده خاموش است. این امن است چون هر قاب فقط مبدأ خود اپ را نشان می‌دهد و پنجرهٔ بازشو و نوار نشانی ندارد.
4. **روی رایانهٔ مالک دیده شد:** میان‌بر منوی Start نسخهٔ ۳۲ بیتی هم‌نام نسخهٔ ۶۴ بیتی بود و آن را جایگزین کرد.
   - نام‌ها به «Payesh (32-bit)» و «Payesh Owner Panel (32-bit)» تغییر کرد و CI آن را بررسی می‌کند.
   - میان‌بر ۶۴ بیتی روی رایانه به حالت قبل برگردانده شد.

## محدودیت‌ها
- **حجم:** نصب‌کننده حدود ۸۰ MB و برنامهٔ باز حدود ۲۲۷ MB است، به‌خاطر Chromium.
- **پین SPKI:** پیوندهای دارای پین (Gateway یا مستقیم) در نسخهٔ ۳۲ بیتی بسته شکست می‌خورند و هرگز بدون پین وصل نمی‌شوند. حالت LAN مدرسه و اتصال‌های HTTPS عادی کار می‌کنند.
- **آزمون روی ویندوز ۳۲ بیتی واقعی:** آزمون روی ویندوز ۳۲ بیتی واقعی (۷ SP1) در دسترس نبود. CI روی Windows Server x64 (WOW64) و رایانهٔ مالک روی ویندوز ۱۰ x64 آزمودند.
