- **offline-first:** همان پایگاه محلی رمزنگاری‌شده، `SqliteOutbox`، `AutoSync` و ادعای مالکیت دستگاهِ موج‌های ۲ تا ۴ استفاده می‌شود (`familyBookFor`).
  - ترتیب کار: بررسی‌ها، بعد صف، بعد نوشتن محلی.
  - نشان «در صف ارسال» و نشان Sync دیده می‌شوند.
  - تصمیم مدرسه با pull بعدی روی دستگاه ولی دیده می‌شود.
- **پرچم:**
  - پیش‌فرض `PAYESH_NATIVE_WAVES` اکنون `login,attendance,grades,notices,parents` است.
  - با `legacy`، با موج خاموش یا وقتی Gateway پیکربندی نشده، خانهٔ ولی می‌گوید «صفحهٔ فرزندان فعلاً در نسخهٔ وب نمایش داده می‌شود.»

سناریوهای IT (W5-IT-01..08):
1. pull فقط دادهٔ خانوادهٔ خود ولی را می‌آورد.
2. معدل و حضور برابر سرور است.
3. درخواست آفلاین ⇒ صف («آفلاین — 1 مورد در صف ارسال») ⇒ پس از اتصال اعمال می‌شود.
4. مدیر تأیید می‌کند و ولی با pull آن را می‌بیند.
5. ولی وضعیت جعلی می‌فرستد ⇒ `approval_denied`.
6. درخواست برای فرزند خانوادهٔ دیگر ⇒ `out_of_scope`.
7. ولی نمره می‌نویسد ⇒ `role_denied`.
8. دبیر صفحهٔ والدین ندارد و هرگز اتصال‌های ولی (parent links) را pull نمی‌کند.
