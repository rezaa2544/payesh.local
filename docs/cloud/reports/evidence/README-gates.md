# شواهد و دروازه‌های تاریخی (شناخت nghiệm)

این فایل وضعیت دروازه‌های شاهدی را که روی پایه‌های قدیمی کار می‌کنند، ثبت می‌کند.

## دروازه‌های منسوخ/تاریخی

| اسکریپت | پایه | وضعیت | دلیل |
|---|---|---|---|
| `review-pr73-integrity.sh` | `f2fc472` (پایهٔ ممیزی PR-73) | **بدون معنی در main کنونی** | این دروازه «تغییر کد محصول = ۰» را نسبت به پایهٔ کهنه می‌سنجد. از آن پایه، کد محصول به‌طور قانونی توسط ردیف‌های ۳۶–۵۴ و ادغام‌های بعدی (مثلاً commits `rezaa2544/payesh.local` روی main) تغییر کرده است. اجرای آن روی HEAD فعلی همیشه `INTEGRITY-FAIL (prod=…)` می‌دهد، حتی اگر تغییری از سوی اجراکننده انجام نشده باشد. آن را **به‌عنوان شاهد تاریخی PR-73** نگهداری می‌کنیم، نه به‌عنوان دروازهٔ زنده. |
| `gen-phase3-gate.sh` | پایهٔ فاز ۳ | **تاریخی** | وابسته به وضعیت同一个 فاز ۳؛ پس از ادغام‌های فازهای بعدی، خروجی آن فقط جنبهٔ سند تاریخی دارد. |

## دروازه‌های زنده (معتبر)

- `gen-audit-evidence.sh` (دروازهٔ شاهد آزمون CI): شاهد `mission-05-tests-run.log` را نسبت به HEAD فعلی و درخت کاری پاک اعتبارسنجی می‌کند — این دروازه زنده و لازم است.
- `run-tests-evidence.sh`: بازسازی شاهد آزمون (append-only).
- `tests/labels-gate-55.js` (پس از PR #136): گیت برچسب‌گذاری قانون اساسی.

## تصمیم

دروازه‌های تاریخی **غیرفعال نمی‌شوند** (سخت‌گیری fail-closed حفظ می‌شود)؛ فقط برچسب «شاهد تاریخی/منسوخ» می‌خورند تا خروجی دائمی `FAIL` گمراه‌کننده نباشد. خروجی آن‌ها فقط باید در بستر تاریخی‌اش تفسیر شود.

## آزمون منفی

اینکه برچسب تاریخی فقط نسخهٔ سند است و دروازه را بی‌صدا غیرفعال نمی‌کند، با اجرای `review-pr73-integrity.sh` نشان داده می‌شود: خروجی همچنان `INTEGRITY-FAIL` است (fail-closed سالم)، ولی دیگر به‌عنوان شکست محصول تلقی نمی‌شود.
