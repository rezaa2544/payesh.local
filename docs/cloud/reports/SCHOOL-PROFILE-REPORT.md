# گزارش ردیف ۱۵۰: فرم مدرسه در پنل مالک فقط مکان/اداره و مدیر؛ بقیهٔ مشخصات در تنظیمات پنل مدیر

**درخواست مالک (۲۰۲۶‑۱۱‑۱۳، با تصویر «تعریف مدرسه جدید»):**
فرم تعریف مدرسه در پنل مالک فقط مکان/اداره و مشخصات مدیر را داشته باشد (برای ساخت حساب مدیر). بقیهٔ مشخصات به تنظیمات پنل مدیر برود و وابستگی‌هایش رعایت شود: نوع، جنسیت، ظرفیت، نوبت، تلفن‌ها، تعدادها، روزهای کاری، بازهٔ موجه و…

## ریشهٔ مشکل

| مشکل | علت |
|---|---|
| فرم شلوغ مالک | فرم p2 همهٔ مشخصات مدرسه را از مالک می‌گرفت، در حالی که مالک این اطلاعات را ندارد و مدیر آن را می‌داند. |
| وابستگی‌ها | قواعد (نوع ⇒ قابلیت‌ها، نوبت ⇒ شبانه، متوسطه دوم ⇒ شاخه) فقط در فرم مالک بود و سرور مدرسه آن‌ها را بررسی نمی‌کرد. |

## چه تغییر کرد

| بخش | تغییر |
|---|---|
| پنل مالک · «تعریف مدرسه جدید» | فقط نام، کد، استان/شهرستان/ناحیه یا روستا، نشانی، فعال، و مدیر (نام، کد ملی، همراه، نام کاربری، رمز). یادداشت `sf-profile-note` می‌گوید بقیه را مدیر تنظیم می‌کند. |
| `payesh_ui` · `school_profile.dart` (تازه) | ثابت‌ها و قواعد مشترک مشخصات مدرسه: نوع ⇒ قابلیت‌ها؛ نوبت «شب» یا «هر دو» ⇒ `has_evening` روشن و قفل؛ «متوسطه دوم» ⇒ دست‌کم یک شاخه؛ با برداشتن شاخه، رشته‌هایش هم حذف می‌شوند؛ تعداد دانش‌آموز ≤ ظرفیت. |
| برنامهٔ کاربر · «سیستم ← مشخصات مدرسه» (مدیر) | صفحهٔ کامل مشخصات با همین وابستگی‌ها. هنگام ذخیره خطای هر فیلد کنار همان فیلد نمایش داده می‌شود. |
| سرور · `server/school-profile.js` + `GET/POST /api/admin/school` | همان قواعد روی سرور (فقط مدیر). کلیدهای مدیر (`managerOwnedKeys`) با فهرست مالک بازنویسی نمی‌شوند. مدرسهٔ ساخته‌شدهٔ مالک بدون این فیلدها با پیش‌فرض‌ها پذیرفته می‌شود (`adoptSchool`). |
| `openapi.yaml` | دو مسیر تازه با `operationId`. |
| CI ردیف ۱۵۰ (رفع در ردیف ۱۵۱) | (۱) افزایش نسخه به 0.9.3 زیپ قفل‌شدهٔ 0.9.2 (کنترل منفی Gate) را از `releases/` حذف کرد.
