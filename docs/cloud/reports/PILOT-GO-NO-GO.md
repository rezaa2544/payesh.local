## ۱. حکم

> **verdict: GO — محدود به پایلوت کنترل‌شدهٔ دو‌مدرسه‌ای، با پنج شرط (پایین).**
>
> **NO-GO برای:** مهاجرت انبوه مدارس، انتشار عمومی چند‌مدرسه‌ای، و هر ادعای SLA/HA.

دلیل: همهٔ معیارهای توقف (S1…S6) در دریل اجرایی **نقض نشدند** و سه بررسی مستقل
(تطبیق محتوا، بازگشت، پایش per-tenant) با اعداد خام سبز شدند؛ اما مقیاس و
زیرساخت تولیدی هنوز اثبات نشده است.

## ۲. شاهد هر معیار

| معیار پذیرش ردیف | نتیجه | شاهد خام |
|---|---|---|
| حداقل دو tenant پایلوت | **PASS** — A (مهاجرت‌شده) و B (فراهم‌شده) هم‌زمان روی PostgreSQL واقعی | `PILOT-RECON` · `PILOT-MON` (دو مستأجر) |
| Migration | **PASS** — ۱۶۶ ردیف، ۸ کالکشن، `imported=166 source_rows=166` | `pilot-migration-drill.txt` |
| Reconciliation | **PASS** — `missing=0 extra=0 differed=0` و `source_hash == target_hash` | `PILOT-RECON … match=1` |
| Rollback | **PASS** — `rows_after=0` برای A، `b_intact=1`، `source_intact=1` | `PILOT-ROLLBACK` |
| idempotency | **PASS** — دو بار re-apply ⇒ همان ۱۶۶ ردیف و همان هش | `PILOT-RECON … phase=reapply` |
| پایش (monitoring) | **PASS** — هر مستأجر: `rows>0`، `cross_tenant_visible=0`، `rls_enforced=true`؛ گزارش کل ناوگان: ۱۷۲ ردیف بدون ردیف بیرونی | `pilot-tenant-monitoring.txt` |

## ۳. آزمون‌های منفی (اثبات اینکه دروازه خالی نیست)

| آزمون | انتظار | نتیجه |
|---|---|---|
| خرابی عمدی یک ردیف در مقصد (بدون تغییر منبع) | reconciliation باید `match=0` بدهد | **گرفته شد** (`PILOT-SELFTEST mismatch_detected=1`) |
| آستانهٔ ناممکن در پایش (`--min-rows=999999`) | پایش باید بحرانی شود، نه ساکت | **exit=2 با `tenant_empty`** |
| درج/خواندن با هدر جعلی مستأجر دیگر | باید در مستأجر خودِ توکن بنشیند و برای دیگری نامرئی باشد | **PASS** (PL‑06) |
| حذف ردیف هم‌شماره در مستأجر دیگر | باید فقط مستأجر خودش را حذف کند | **PASS** (PL‑07) |

## ۴. پنج شرطِ GO (رعایتشان اجباری است)

1. **پایلوت فقط با دو مدرسهٔ داوطلب** و رضایت کتبی مدیر مدرسه؛ هیچ دادهٔ واقعی خارج از این دو.
2. **پنجرهٔ مهاجرت با نوشتن متوقف** + پشتیبان منبع؛ بدون آن مهاجرت اجرا نمی‌شود.
3. **تطبیق سه‌لایه** (تعداد/محتوا/هویت) پیش از بازکردن نوشتن در مقصد؛ ناهمخوانی ⇒ توقف و rollback.
4. **پایش هر ۵ دقیقه** با `scripts/pilot-tenant-report.mjs` و `scripts/healthcheck.mjs`؛ نقض آستانه ⇒ P1 و توقف رشد پایلوت.
5. **بدون ادعای SLA/HA/ظرفیت تولیدی**: اعداد این سند روی یک میزبان با PostgreSQL موقت است.

## ۵. معیارهای توقف (خلاصه)

| # | معیار | آستانه | اقدام |
|---|---|---|---|
| S1 | نشت بین‌مستأجری | ۰ | توقف فوری + حادثه |
| S2 | ناهمخوانی reconciliation | ۰ | توقف + rollback مقصد |
| S3 | از دست رفتن دادهٔ منبع | ۰ | توقف + بازیابی از پشتیبان |
| S4 | rollback خارج از محدوده یا > ۵ دقیقه | ۰ | توقف + بررسی دستی |
| S5 | `rls_enforced=false` | ۰ | توقف فوری |
| S6 | مستأجر خالی/کهنه | ۰ | هشدار و بررسی |

## ۶. آنچه این سند اثبات **نمی‌کند**

- خوشهٔ PostgreSQL تولیدی، چند‌ناحیه‌ای، backup خودکار مقصد، و failover.
- زمان مهاجرت در مقیاس (هزاران ردیف تا صدها هزار) — دریل با ۱۶۶ ردیف اجرا شد.
- بار واقعی هم‌زمان چند مدرسه در ساعات اوج (ردیف ۲۹ فقط ظرفیت تک‌میزبان را سنجیده).
- پیجر/on-call شبانه‌روزی (BC‑16‑۲ — تصمیم مالک).
- امنیت کل محصول: وضعیت همچنان `UNKNOWN` (شاهد‌محور) است؛ این سند فقط می‌گوید
  **این سناریوی پایلوت** با این معیارها سبز شد.
