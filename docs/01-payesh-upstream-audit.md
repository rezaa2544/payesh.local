## ۱. خلاصهٔ مدیریتی

«پایش» یک **SIS کامل (سامانهٔ اطلاعات دانش‌آموزی) + لایهٔ خدمات جانبی مدرسه** است، نه یک برنامهٔ حضور و غیاب ساده. سه لایه دارد:

| لایه | چیست | برای لوکال |
|---|---|---|
| **کلاینت** (`src/` → `build.js` → `index.html`) | برنامهٔ کامل فارسی/RTL، تک‌فایلی، آفلاین‌محور، با IndexedDB و صف همگام‌سازی. ۳۴٬۰۹۱ خط در ۹۱ فایل، خروجی ۱٫۷ مگابایت و ۲۸٬۰۴۷ خط HTML بدون هیچ CDN خارجی | **نگه می‌داریم** (سرمایهٔ اصلی پروژه) |
| **سرور** (`server/`) | Node 22، ۵۰٬۸۶۹ خط در ۱۲۳ فایل: احراز هویت، sync، pull دلتا، مجوز، PostgreSQL، Redis، outbox، metrics، WAF، canary، DR | **بازنویسی سبک** (فقط ۸ تا ۱۲ مسیر لازم است) |
| **زیرساخت مقیاس ملی** (`infra/`, `server/infrastructure/`, `migrations/` ۲۶ عدد) | چندمدرسه‌ای، پارتیشن‌بندی، HA، ظرفیت ۱۰M، DR، load/chaos test | **کنار می‌گذاریم** |

نتیجهٔ کلیدی: **۹۰٪ ارزش محصول در کلاینت و مدل داده است، نه در زیرساخت ملی.** نسخهٔ لوکال یعنی «همان رابط، با یک سرور اسباب‌بازی که یک مدرسه را اداره می‌کند».

## ۳. معماری فعلی (فهم دقیق)

```
┌────────────────────────────── کلاینت ──────────────────────────────┐
│ index.html (تک‌فایل)                                                │
│  ├─ 00-data-layer.js   ← تنها دروازهٔ داده؛ DATA_MODE = 'local'|'server' │
│  ├─ 03-persistence.js  ← دفترچهٔ عملیات (op-log) + snapshot          │
│  ├─ 03-idb-persistence.js ← IndexedDB (payesh_offline_v2)           │
│  ├─ 28-indexes.js      ← ایندکس O(1) با نسخه‌بندی                    │
│  ├─ 29-scope.js        ← مرز داده بر اساس نقش/مدرسه/فرزند            │
│  ├─ 30-authz.js        ← مجوز fail-closed                            │
│  ├─ 27-sync.js         ← صف ارسال (pending→sending→synced/rejected)  │
│  ├─ 29-pull.js         ← دریافت دلتا + cursor امضاشده                │
│  ├─ 68-sync-conflicts.js ← UI حل تعارض                               │
│  └─ ۲۳ ماژول فارسی: داشبورد، حضور، نمره، انضباط، برنامه، مالی…        │
│  sw.js + manifest.json ← PWA + Background Sync                       │
└─────────────┬──────────────────────────────────────────────────────┘
              │  خودکار: GET /api/health ⇒ اگر ok بود ⇒ DATA_MODE='server'
              ▼
┌────────────────────────────── سرور ────────────────────────────────┐
│ server/index.js  (Node 22، استاندارد lib + pg + ioredis + OTel)     │
│  /api/health /api/readiness /api/liveness                            │
│  /api/auth/*  (phone + OTP + national_id → JWT در HttpOnly cookie)   │
│  POST /api/sync  (صف نوشتن: field-gate, scope, idempotency, OCC,     │
│                   conflict-preservation, tombstones, audit)          │
│  GET /api/v1/pull (دلتای DB-native + cursor)                         │
│  /api/students/:id /api/bell/now /api/public-report /api/admin/*     │
│  PostgreSQL = منبع حقیقت   ·   Redis = cache/rate-limit/revocation   │
│  outbox + worker + queue   ·   metrics + tracing   ·   WAF          │
└─────────────────────────────────────────────────────────────────────┘
```

**نکتهٔ حیاتی برای لوکال:** کلاینت خودش تشخیص می‌دهد «سرور واقعی پشت من است یا نه». اگر برنامه از یک HTTP/HTTPS سرو شود و `/api/health` جواب `{"ok":true}` بدهد، کلاینت خودکار به حالت سروری می‌رود و صف همگام‌سازی را روی `/api/sync` فعال می‌کند. **یعنی نقطهٔ اتصال نسخهٔ لوکال، فقط پیاده‌سازی همین چند مسیر است؛ نه بازنویسی رابط.**

## ۴. نقش‌ها و مدل مجوز

۹ نقش در `authz/model.json` (منبع واحد مجوز، با تولید `authz/write-perms.json` و گیت build):

| نقش فنی | فارسی | مأموریت | در لوکال |
|---|---|---|---|
| `manager` | مدیر مدرسه | همه‌چیز مدرسه | ✅ نقش اصلی |
| `teacher` | دبیر | کلاس‌های خودش: حضور، نمره، تکلیف، انضباط، مرخصی | ✅ |
| `student` | دانش‌آموز | برنامه، نمره، حضور، کارنامه، تکلیف، کتابخانه، شهریه | 🔶 اختیاری |
| `parent` | ولی | پرونده چند فرزند، نمره، حضور، اطلاعیه، پیام، جلسه، مالی | ✅ |
| `counselor` | مشاور | صف ارجاع، پرونده مشاوره، یادداشت محرمانه | ✅ |
| `guard` | نگهبان | ثبت ورود/خروج مراجعین | 🔶 اختیاری |
| `driver` | راننده سرویس | مسیر خودش، سوار/پیاده | 🔶 اختیاری |
| `superadmin` | مدیر کل سامانه | پلتفرم، مدارس، اشتراک، سلامت | ❌ حذف (تک‌مدرسه) |
| `edu_office` | ادارهٔ آموزش‌وپرورش | دید تجمیعی منطقه‌ای | ❌ حذف |

مجوزها **در سطح فیلد و عمل** تعریف شده‌اند: برای هر کالکشن، مجموعهٔ فیلدهای مجاز و نقش‌های مجاز `ins/upd/del`. هر فیلد یا کالکشن ناشناس = **رد** (fail-closed). همین فایل دقیقاً برای سرور لوکال هم قابل استفاده است.

> سوییچ نقش (`S.persona`) وجود دارد: یک نفر می‌تواند هم‌زمان دبیر و ولی باشد و بین پنل‌ها جابه‌جا شود.

### ۶.۱۰ فقط شبیه‌سازی دمو (باید لوکال جایگزین شود)

1. **پیامک**: پنل پیامکی داخل برنامه، کد را روی صفحه نشان می‌دهد؛ هیچ پیامکی ارسال نمی‌شود.
2. **استعلام کد ملی**: جست‌وجو در همان دادهٔ دمو، نه سامانهٔ واقعی.
3. **پرداخت**: فقط رکورد تراکنش.
4. **اشتراک/پی‌وال**: مدل کسب‌وکار نسخهٔ ملی؛ در مدرسهٔ خودتان معنا ندارد.
5. **دادهٔ نمونه**: ۱۰۴۰ کاربر، ۶ مدرسه، ۱۲٬۸۵۵ نمره — قطعی و بازتولیدپذیر (خود مخزن هشدار می‌دهد این هرگز نباید پایهٔ هویت واقعی شود).

## ۷. چه چیزی برای مقیاس ۱۰ میلیون ساخته شده و در مدرسه لازم نیست

این‌ها را **حذف یا خاموش** می‌کنیم؛ حذف‌شان نه‌فقط آسان است، بلکه امنیت و سادگی را بالا می‌برد:

- multi-tenant + `tenant_policy` + geographic isolation
- Redis (کش، rate-limit توزیع‌شده، ابطال نشست، OTP state)
- outbox/distributed queue، canary deployment، WAF، attack detector
- پارتیشن‌بندی `grades`/`attendance`، PgBouncer، read replica، weighted partitioning
- national capacity enforcement، chaos/load testing، DR multi-region
- superadmin، edu_office، provinces/counties/districts/offices، subscriptions/paywall
- OpenTelemetry + tracing + Prometheus (در حد یک لاگ ساده کافی است)

**اما این چهار قرارداد را نگه می‌داریم** چون همان‌ها داده را سالم نگه می‌دارند:
1. مجوز فیلد-سطحی fail-closed، ۲. OCC + tombstone + idempotency در sync، ۳. audit، ۴. scope داده.

## ۹. آزمون عملی (شاهد اجرایی)

برای اطمینان از اینکه «سرور واقعاً کار می‌کند و چقدر سبک است»، در همین محیط:

```bash
npm ci                       # ۱۹۴ بسته، ۴ ثانیه
node server/seed.js          # ساخت duniaی دمو: 1040 کاربر، 6 مدرسه، 12855 نمره
PAYESH_JWT_SECRET=… PORT=8899 node server/index.js
```

خروجی:

```json
GET /api/health  →  {"ok":true,"name":"payesh-server","db":{"driver":"memory"},
                     "redis":{"driver":"memory"},"memory":{"heap_used_kb":31321}}
GET /            →  200  (1,691,008 bytes — همان index.html)
```

یعنی:
- سرور **بدون PostgreSQL و بدون Redis** بوت می‌شود (fallback JSON) و اپ را سرو می‌کند.
- مصرف حافظه در حالت سکون ~۳۱ مگابایت؛ روی یک مینی‌پی‌سی معمولی بی‌مسئله است.
- همین رفتار نشان می‌دهد «نسخهٔ لوکال» از نظر منابع سخت‌افزاری هیچ محدودیتی ندارد؛ محدودیت اصلی **طراحی هویت/امنیت و عملیات** است، نه ظرفیت.

> هشدار: حالت JSON/حافظه‌ای برای دادهٔ واقعی مناسب نیست (بدون تراکنش، بدون بکاپ تراکنشی، بدون قفل). نسخهٔ لوکال باید SQLite داشته باشد.
