امضای انتشار اندروید — فقط با کلید تحت کنترل Owner
======================================================

قواعد اجرایی
------------
- هیچ keystore، رمز، alias خصوصی یا فایل base64 کلید در Git commit نمی‌شود.
- نسخهٔ release در CI فقط با Secrets زیر ساخته می‌شود:
  PAYESH_KEYSTORE_B64, PAYESH_KEYSTORE_PASS, PAYESH_KEY_ALIAS, PAYESH_KEY_PASS
- PAYESH_KEYSTORE_B64 محتوای PKCS12 را به‌شکل base64 نگه می‌دارد؛ CI آن را موقتاً در RUNNER_TEMP می‌نویسد و پس از پایان job از بین می‌رود.
- build محلی debug از کلید debug استاندارد Android استفاده می‌کند. ساخت release بدون چهار ورودی امن fail-closed است؛ کلید ثابت داخل مخزن یا fallback عمومی وجود ندارد.
- هیچ Secret، مقدار، رمز یا محتوای keystore را در گزارش، issue، chat، فایل محلیِ commit‌شونده یا خروجی CI چاپ نکنید.

مالکیت و چرخش کلید
------------------
1. Owner یک کلید خصوصی تازه را آفلاین/در محیط امن و با فرایند تأییدشده تولید و پشتیبان‌گیری می‌کند. Arena این کلید را تولید، دریافت یا نگهداری نمی‌کند.
2. Owner تصمیم می‌گیرد چگونه نصب‌های قبلی را بدون قطع به‌روزرسانی منتقل کند. حذف فایل از HEAD به‌تنهایی اثر تاریخچهٔ Git را پاک نمی‌کند؛ انتشار کلید قبلی در مخزن عمومی به‌معنای افشای آن است و نباید دوباره استفاده شود.
3. بازنویسی تاریخچه فقط با اجازهٔ صریح Owner انجام می‌شود. تا آن زمان هیچ force-push یا بازنویسی تاریخچه‌ای انجام نمی‌شود.
4. Owner کلید جدید و مقادیر لازم را مستقیماً در GitHub Actions Secrets تنظیم می‌کند؛ آن‌ها را برای Arena ارسال نکند. پس از تنظیم، CI باید گیت منفی را (تزریق آزمایشی را رد کند)، ساخت release را با کلید جدید انجام دهد و امضا/گواهی APK را تأیید کند.
5. پیش از انتشار عمومی، Owner باید مسیر نصب‌های موجود را مستند و تأیید کند: چرخش سازگار Android APK Signature Scheme v3 که واقعاً پیاده‌سازی و آزموده شده باشد، یا پذیرش روشنِ نیاز به حذف و نصب دوباره. پس از این تصمیم، Owner متغیر مخزن `PAYESH_SIGNING_ROTATION_APPROVED=true` را تنظیم کند؛ Gradle و workflow تا آن زمان fail-closed هستند.
6. این متغیر فقط تأیید Owner است، نه اثبات فنی چرخش. workflow امضای APK و schemeهای v2/v3 را بررسی می‌کند، اما خودِ سازگاری نصب روی دستگاه‌های دارای نسخهٔ قبلی را اثبات نمی‌کند؛ آن باید جداگانه با مسیر انتخاب‌شده آزموده شود.

وضعیت فعلی
-----------
فایل keystore و رمز ثابت از درخت فعلی حذف شده‌اند. این تغییر ادعای پاک‌شدن تاریخچه نیست. ساخت release تا زمانی که Owner Secrets را بسازد و مسیر انتقال کلید را تأیید کند، عمداً ناموفق می‌شود. هیچ کلید یا Secret در این سند ثبت نشده است.
